# 2.0 Storytelling with Git

▶ [Watch in the video (37:29)](https://www.youtube.com/watch?v=7x6C8_FXEK0&t=2249s)

Section 1 covered the basic operations, which make up most of day-to-day Git use. But it
leaves a question open: why work with commits and branches at all, when there are other
ways to save and share code?

The answer this section offers is that Git lets you **tell the story of your project**.
Through branches, commits, and their messages, you can deliberately craft a project
history that means something to other people: what was tried, what was kept, and why.

The modules that follow each take one storytelling use case. Each starts conceptually,
then moves to a hands-on example in the `git-tutorial` clone from section 1:

- [2.1 Choose Your Own Adventure](01-choose-your-own-adventure.md): developing in parallel
- [2.2 Get Your Story Straight](02-get-your-story-straight.md): reconciling parallel work
  into a linear history
- [2.3](03-control-the-narrative-backups-and-undoing-commits.md)–[2.6](06-control-the-narrative-force-pushing.md)
